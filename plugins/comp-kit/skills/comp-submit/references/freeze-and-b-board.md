# B 榜冻结与终榜流程

多数 CV / 语音赛制：A 榜（公开测试集，每日额度）→ B 榜前登记冻结 `solution.zip`
（SHA-256 + 精确字节数）→ B 榜（隐藏测试集，累计额度，成绩才算数）→ 前 N 名代码复现审核。
**A 榜成绩常不计入最终成绩**，B 榜才是交付点。

## 1. 时间线（自设缓冲，不要和候选研发抢时间）

| 节点 | 动作 |
|---|---|
| A 榜截止前 N−3 天 | 演练打包：单入口脚本、依赖导出、README、逐字节回归 |
| A 榜截止前 N−1 天 | **方案构成锁定截止**，此后只做复核不改方案 |
| A 榜截止后 | 择线上验证过的最优配方定冻结基座 |
| B 榜发布前 | 登记 SHA-256 + 精确字节数；本地 `chmod 444` + 另存 `solution.frozen.zip` |
| B 榜发布后 | 冻结包一字不改；只出 B 榜预测包并提交 |

冻结基座维持**唯一被线上实测验证过**的配方，不因离线数字更好而替换；
发布前若有新的线上验证增益（如 +0.0012 已兑现），替换登记包合规且值得。

## 2. 冻结检查单

- [ ] **权重清单**：每个成员的路径 + SHA-256 + 字节数；跨机器复算一致。
- [ ] **单入口脚本**：从测试集信息文件直接产出提交文件，固定冻结参数、无任何选择逻辑；
      `--device {cpu,mps,cuda}` 参数化，CUDA 限显存代码放 cuda 分支；golden 字节门改为可选。
- [ ] **依赖**：`uv export` 出 pin 版本的 `requirements.txt`；确认复现环境 Python / torch 版本
      （官方未写就在登记页截图核对），必要时降级重验并预留半天。
- [ ] **离线可运行**：`HF_HUB_OFFLINE=1` 下跑通；`grep -rn "pretrained=True"` 为空
      （必须 `pretrained=False` + 本地权重）；清掉 `all_proxy` 类环境变量再测一次
      （畸形代理配置会让 httpx 在构造阶段崩，错误看起来像缺权重）。
- [ ] **确定性**：不用随机 TTA；复现 Δ 须 ≤ 平台规定（如 0.005）。
- [ ] **体积**：权重去重（五折 checkpoint 间逐位相同的张量只存一份，实战省 67%）；
      总体积低于平台硬限（1 GB 类），超限静默被拒。
- [ ] **README 与披露**：一步复现命令、预期输出指纹、运行时长、硬件建议；
      预训练权重来源 / 许可（AGPL、研究许可等非标准许可显式标注）、外部数据声明、
      合成数据工具未参与真实训练的说明。
- [ ] **逐字节回归**：解压到临时目录按 README 全流程跑 A 榜图，产出与线上最佳包逐位一致。
      跨设备（CUDA 生成、CPU 复核）无法逐字节时，标准改为「同端重跑 + 逐记录 IoU > 0.999 +
      官方校验 PASS」，并在 README 声明浮点差异。
- [ ] **登记**：SHA-256 + 精确字节数（`stat` / `ls -l`，不是近似值）；登记后硬刷新复验条目数为 1。
- [ ] **多臂包**（用环境变量切换成员时）：规则解释先向官方 / 用户确认；每臂单独回归。

## 3. B 榜运行纪律

- **第 1 发必须是冻结基座原样**，不用 B 榜额度打探针。
- B 集发布靠守夜脚本监控（模式见 comp-campaign），下载后先 audit：图数 / 视频数 / 缺失 0。
- 出包链每一步落盘计数；判「在推进」看产物增量，不看进程存在。
- 最终成绩取最后一次有效提交时，最优包安排在最后；取历史最优时，同包保险复投防单条失效。
- 官方校验器对退化几何（< 1 px 宽多边形）拒收，出包前过一遍与官方相同的过滤。
- B 榜若发现管线问题：不得改 solution.zip；只允许改不依赖冻结口径的出包参数，
  宁可用冻结管线原样出包。

## 4. 换赛段（复赛 / 决赛）

- 第一发用已知分数的历史包精确复现，验证评测口径没变。
- 重核隐藏集结构（trial 数、场景分布）与剩余额度；旧规律的方向与幅度全部重验。
