# comp-submit：提交管理

每日提交次数是竞赛里最稀缺的资源。leaderboard 反馈是唯一来自真实测试分布的信息，
每一次提交都应当**要么验证管道、要么回答一个问题、要么刷新最优**——三者都不占的提交是浪费。

## 提交前校验（脚本化，不靠肉眼）

维护一个校验脚本 `src/check_submission.py`——**从本 skill 的
`assets/check_submission.py` 脚手架拷贝**。提交物支持单文件 / 目录 / ZIP 包三种形态，
按比赛定制三处：

- `MANIFEST`：提交物形态与包内清单（必需条目、禁止条目 glob、体积上限；
  ZIP 自带路径安全检查）；
- 条目 Spec：`Table`（列序 / 行数 / 解析 / 取值 / 缺失 / 官方 demo 逐列 diff——
  最强格式校验）或 `File`（存在性 / 体积 / 自定义 loader，如 json、npy、权重文件）；
- `@rule` 函数：领域合法性规则，一个假设一个函数，可跨条目（如 config 与 results
  一致性）；按组断言用 `@per_group("<条目>")` 包装，自动汇总"N/N 组合法"。

任一 FAIL 退出码为 1，可挂 pre-submit hook / CI；全部通过时输出 MD5 与
experiment-log 粘贴块（`--log-snippet`），与 comp-experiment 的记录闭环。

每次提交前跑，逐项断言：

1. **格式**：文件名、列名与顺序（注意中文列名）、行数公式、时间/ID 格式、编码。
   与官方 demo 文件逐列 diff 是最稳的实现。
2. **合法性**：输出满足全部硬约束（如窗口连续性、取值范围、每日限制）。
   逐天/逐样本断言，输出 `59/59 天合法` 这类全量结论。
3. **留痕**：算 MD5，连同生成脚本与配置记入 `docs/experiment-log.md`。
   提交上传后官网若显示文件 hash，回来核对。

一次因为列名顺序被拒的提交 = 白烧当天 1/3 的预算。

## 提交预算规划

把每天 N 次提交当预算分配，动手前想清楚今天的每一发买什么：

- **管道验证发**：新赛段 / 新账号 / 管道改动后的第一发，用已知分数的历史文件
  **精确复现**——分数对上（小数点后全对）才证明评测口径没变、管道可信。
  对不上就停下排查，不要在不可信的管道上继续花预算。
- **探针发**：回答一个明确问题（见下节）。
- **冲榜发**：当前最优候选。留出当天至少一发给"已知最优回滚"，防止实验发全负后榜上无新高。

每条提交记录账号与剩余次数（experiment-log 格式已含）。当日预算用尽就停手，
把想法写进 working-notes 明天验证——深夜冲动提交是负期望行为。

## 探针提交（probe）

线上反馈少而贵，探针的设计原则和离线实验一样：**单变量**。

- 一发探针只改一个维度：如"全体交易日放电窗口统一 −2"、"只改某一天的窗口"。
  得分差即该变量的边际效应。
- 围绕当前最优做小扰动族（−1 / −2 / −3），把得分差画成曲线找峰值——
  少数据点下用倒 U / 二次曲面这类最简单的形状假设，别拟合复杂模型。
- **警惕单日噪声**：批量改动的净效应可能是"多数日小赚 + 个别日大亏"。
  改动天数要记录（如 `改变 20/59 天`），效应要按天可分解时尽量分解。
- 离线信号与线上反馈冲突时，**在漂移场景下信线上**——但确认不是管道问题（先做精确复现）。

## 多账号调度（规则允许时）

- 每个账号记录：历史最优分、今日剩余次数、上一发内容。
- 探针分散到非最优账号打，最优账号保持"榜上最优 + 保底回滚"职责。
- 新高出现后，把新高文件回填为权威 `submissions/output.csv` 并记 MD5，
  其他账号后续以它为扰动基底。

（注意各平台对多账号的规则差异，禁止多账号的比赛严格单账号。）

## 线上反馈的保守利用

测试集无真值、天数有限时，线上得分序列本身就是训练数据——但只有个位数样本点：

- 只做**全局、低自由度**的拟合：统一位移、统一缩放、分组常数。
  逐日自由参数 = 对噪声过拟合。
- 每个从线上反馈归纳出的"规律"都标注适用边界（哪个测试集、哪个 regime），
  换赛段必须重新探测——这是复盘文档（comp-retrospective）的核心输入。
