# comp-submit：提交管理

每日提交次数是最稀缺的资源，leaderboard 是唯一来自真实测试分布的信息。每一发要么验证管道、要么回答
一个问题、要么刷新最优，三者都不占的提交是浪费。七题实战里主动弃投的候选比投出的多：**额度作废优于
噪声提交**。

## 提交前：校验 + 门禁，两道都过才进队列

**格式校验**用 `src/check_submission.py`（从 `assets/check_submission.py` 拷贝；支持单文件 / 目录 / ZIP，
按比赛定制 `MANIFEST` 与 `@rule` 函数，一个假设一个函数）。任一 FAIL 退出码 1；全过输出 SHA-256、
精确字节数、MD5 与日志粘贴块。要逐项断言的陷阱（每条都咬过人）：

- 列名与顺序、行数公式、时间 / ID 格式、编码、分隔符、首行特殊值。
- 训练标注 id 与提交 id 的映射（训练 1/2 → 提交 0/1，差一位两类全错）。
- 掩膜编码（compressed RLE 的 `counts` 要 `.decode()`；`size` 是 `[h, w]`；恢复到原图分辨率）。
- 每张测试图必须且只能出现一次；无预测填空列表而不是省略。
- 官方校验器丢弃越界 / 退化记录是静默的，本地先过一遍同样的过滤。官方给了 demo 文件就逐列 diff，
  给了 formatcheck 脚本就一并跑。

**准入门禁**用 `src/gate_candidate.py`（脚手架 `assets/gate_candidate.py`，设计见 comp-experiment
`references/gate-design.md`）：方向门（瓶颈维度不恶化）、主门（同口径 ≥ 阈值）、否决门（代价侧不恶化）、
暴露度门（相对线上锚点 ≥ 门槛），exit 0 才进队列。弃投是正确产出，不因「今天还没投过」降低标准。
run 目录里与真候选结构完全相同的中间产物肉眼不可分，任何产物提交前都自己重跑门禁。
例外：用户明确指示探索性用完额度，或做标定探针时，可投已关闭方向的候选，但每发仍要预登记判读。

## 一次提交的三层证据

「文件传上去了」和「作品提交了」是两件事。判成功要三层都对上：

| 层 | 证据 | 实战陷阱 |
|---|---|---|
| 传输 | 平台对象回读（下载后 `shasum -a 256`）与本地逐字节一致 | S3 兼容端点静默损坏分块上传，对象大几十字节、开头是 ASCII，平台只报「运行环境异常」 |
| 受理 | 额度确实减 1，刷新后仍是减后的值；提交记录出现 | 表单「提交」后还有「确认提交作品？」模态框，漏点则文件在 S3 上、额度不扣、零记录 |
| 评分 | 分数出现，与预登记判读对照 | 同一 SHA 先成功后失败 ⇒ 平台侧问题，通常退额；不自动当平台问题重提 |

回执用 `src/receipts.py add` 登记（脚手架 `assets/receipts.py`，字段见 `references/receipt-schema.md`），
它会校验额度是否减 1、回读是否一致，缺硬证据标「不可验」；出分后 `receipts.py score` 回填。
浏览器投递若终点击被权限拦截，回执写「未投」。

## 额度预算：每一发买什么

- **管道验证发**：新赛段、新账号、管道改动后的第一发，用已知分数的历史文件精确复现。小数点后全对
  才证明评测口径没变，对不上就停下排查。
- **探针发**：回答一个明确问题，单变量，预登记判读（落在哪个区间意味着什么、之后做什么 / 不做什么），
  出分后按判读处置，不临场解释。围绕当前最优做小扰动族，记录暴露度。
- **冲榜发**：当前最优候选，留至少一发给「已知最优回滚」。
- **标定探针**：A 榜不计入最终成绩且榜取历史最优时，已关闭方向的候选可以投出去校准离线↔线上映射，
  回执照常登记，`receipts.py calibrate` 会把它算进标定库。
- 累计额度（如 B 榜累计 3 发）与每日额度分开记账；当日预算用尽就停手，深夜冲动提交是负期望行为。
- 规则允许多账号时，探针分散到非最优账号，最优账号保持「榜上最优 + 保底回滚」。

线上反馈的利用要保守：测试集无真值、样本点个位数时只做全局、低自由度的拟合（统一位移 / 缩放 /
分组常数），逐日 / 逐样本自由参数就是对噪声过拟合。离线与线上冲突时在漂移场景下信线上，但先做精确复现
排除管道问题。每条从线上归纳的规律标注适用边界，换赛段重新探测。

## 平台通道陷阱

- 上传入口与打分入口是两回事：在打分入口上传冻结包等于白烧额度且没登记上。
- 导航 tab 不渲染 ≠ 版块未开放，直接带路由参数访问；「前 N 名需提交源码」是要求说明不是访问控制。
- B 榜可能是独立赛题 ID（额度、榜单、记录独立），用 A 榜 ID 加 stage 参数查会返回空，误判成「提交丢失」；
  页面「提交结果」表可能只显示 A 榜记录，以额度扣减为准。
- 队名可能显示为随机串，定位自己用分数 + 最佳成绩提交时间双重比对；榜单快照存 JSON。
- 平台代码上传有硬体积上限（如 1 GB），超限静默被拒。
- 浏览器自动化投递的终点击可能触发权限拦截，A / B 榜授权不互相外推；多赛题时派提交子代理（comp-campaign）。

## B 榜冻结与换赛段

冻结死线比提交死线早：solution.zip 须在 B 榜测试集**发布前**登记 SHA-256 + 精确字节数，发布后任何改动
即取消成绩。条款边界是「发布后」而非「上传后」，发布前替换登记包合规，这决定最后几小时能否把已验证
增益写进最终成绩。最终成绩取「最后一次有效提交」还是「历史最优」决定 B 榜投递顺序，B 榜前问清。
完整时间线、冻结检查单、B 榜运行纪律与换赛段验证见 `references/freeze-and-b-board.md`。
