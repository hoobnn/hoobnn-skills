# comp-submit：提交管理

每日提交次数是竞赛里最稀缺的资源。leaderboard 反馈是唯一来自真实测试分布的信息，
每一次提交都应当**要么验证管道、要么回答一个问题、要么刷新最优**——三者都不占的提交是浪费。
七题并行实战里主动弃投的候选比实际投出的多，**额度作废优于噪声提交**。

## 提交前校验（脚本化，不靠肉眼）

维护 `src/check_submission.py`——从本 skill 的 `assets/check_submission.py` 脚手架拷贝。
提交物支持单文件 / 目录 / ZIP 三种形态，按比赛定制 `MANIFEST`、条目 Spec、`@rule` 函数
（一个假设一个函数，按组断言用 `@per_group` 包装，输出「N/N 组合法」）。
任一 FAIL 退出码 1；全部通过时输出 SHA-256、精确字节数、MD5 与 experiment-log 粘贴块。

必须逐项断言的格式陷阱（实战每条都咬过人）：

- 列名与顺序（中文列名）、行数公式、时间 / ID 格式、编码、分隔符（空白分隔 vs 逗号）、
  首行特殊值（如 GFLOP）。
- **训练标注 id 与提交 id 的映射**（训练 1/2 → 提交 0/1，差一位两类全错）。
- 掩膜编码（compressed RLE 的 `counts` 必须 `.decode()`；`size` 是 `[h, w]`；恢复到原图分辨率）。
- 每张测试图必须且只能出现一次；无预测填空列表而不是省略。
- 官方校验器丢弃越界 / 退化记录是**静默**的，本地要先过一遍同样的过滤。
- 官方 demo 文件逐列 diff 是最稳的实现；官方给了 formatcheck 脚本就一并跑。

## 准入门禁：格式通过 ≠ 可以投

`check_submission.py` 只验格式，不验值不值得消耗额度。每个候选还要过
`src/gate_candidate.py`（脚手架在 `assets/gate_candidate.py`，设计见
comp-experiment 的 `references/gate-design.md`）：方向门（瓶颈维度不恶化）、
主门（同口径 ≥ 阈值）、否决门（代价侧不恶化）、暴露度门（相对线上锚点 ≥ 门槛）。
exit code 0 才进提交队列。

- **弃投是正确产出**，不因「今天还没投过」降低标准。
- 同一目录里与真候选结构完全相同的中间产物（同实例数、只差 `category_id`）肉眼不可分，
  **任何产物提交前都必须自己重跑门禁**，「run 目录里有个 composed 文件」不构成证据。
- 例外：用户明确指示「探索性用完今日额度」或做标定探针（见下节）时，
  可用已关闭方向的候选，但每发仍要预登记判读。

## 一次提交的三层证据

「文件传上去了」和「作品提交了」是两件事。判成功的**唯一硬证据**是下面三层都对上：

| 层 | 证据 | 实战陷阱 |
|---|---|---|
| 传输层 | 平台对象回读（下载后 `shasum -a 256`）与本地逐字节一致 | S3 兼容端点静默损坏分块上传，对象大几十字节、开头是 ASCII；平台只报「运行环境异常」 |
| 受理层 | `remain` 额度**确实减 1**，刷新后仍是减后的值；提交记录出现 | 表单「提交」后还有一个「确认提交作品？」模态框，漏点则文件在 S3 上、额度不扣、零记录 |
| 评分层 | 分数出现，与预登记判读对照 | 同一 SHA 先成功后失败 ⇒ 平台侧问题，失败通常退额；不自动当平台问题重提 |

写回执时把额度前后值、回读指纹、提交时间一起记，不要只写「已投」。
回执字段见 `references/receipt-schema.md`。

## 提交预算规划

把每天 N 次当预算，动手前想清楚今天每一发买什么：

- **管道验证发**：新赛段 / 新账号 / 管道改动后的第一发，用已知分数的历史文件**精确复现**——
  分数小数点后全对才证明评测口径没变。对不上就停下排查。
- **探针发**：回答一个明确问题（单变量），**预登记判读**：得分落在哪个区间意味着什么、
  之后做什么 / 不做什么。
- **冲榜发**：当前最优候选，留至少一发给「已知最优回滚」。
- **标定探针**：A 榜不计入最终成绩、榜取历史最优时，已关闭方向的候选可以投出去
  校准离线↔线上映射（不损名次），每发同样预登记判读；这类数据点汇入 comp-experiment 的标定库。
- **A 榜是否计入最终成绩**改变每一发的价值：只有 B 榜算时，A 榜末日冲榜没有名次价值，
  真正的交付点是冻结包。

累计额度（如 B 榜累计 3 发）与每日额度分开记账；当日预算用尽就停手，深夜冲动提交是负期望行为。

## 探针提交（probe）

- 一发探针只改一个维度；围绕当前最优做小扰动族，少数据点下用最简单的形状假设。
- 改动天数 / 实例数要记录（暴露度），效应按可分解维度分解。
- 离线信号与线上反馈冲突时，在漂移场景下信线上——但先做精确复现排除管道问题。
- 探针出分后立即按预登记判读处置，不临场解释。

## 赛程与冻结条款：以规则正文为准

- **不信 API 字段、不信页面「报名截止」**：`prelimEnd` 类字段常是整体结束日，
  真实 A/B 榜窗口只在规则正文的【赛程周期】里；用官方服务器时间接口算剩余时间。
- **冻结死线比提交死线早**：solution.zip 须在 B 榜测试集**发布前**登记 SHA-256 + 精确字节数，
  发布后任何改动即取消成绩。冻结条款的边界是「发布后」而非「上传后」——
  发布前替换登记包合规，这个区别决定最后几小时能否把已验证增益写进最终成绩。
- 同平台不同赛题的外部数据 / 预训练 / 冻结口径互相冲突，**勿互抄**。
- 最终成绩取「最后一次有效提交」还是「历史最优」决定 B 榜投递顺序，B 榜前务必问清。
- 冻结检查单与 B 榜流程见 `references/freeze-and-b-board.md`。

## 平台通道陷阱清单（通用化，具体平台的细节写进仓库 docs）

- 上传入口与打分入口是两回事：在打分入口上传冻结包等于白烧一次额度且没登记上。
- 导航 tab 不渲染 ≠ 版块未开放，直接带路由参数访问；「前 N 名需提交源码」是要求说明不是访问控制。
- B 榜可能是独立赛题 ID（额度、榜单、记录独立），用 A 榜 ID 加 stage 参数查会返回空，
  误判成「提交丢失」。
- 页面「提交结果」表可能只显示 A 榜记录，B 榜投递永远不在那张表里；以额度扣减为准。
- 队名在不同赛题可能显示为随机串，定位自己用**分数 + 最佳成绩提交时间**双重比对。
- 榜单快照存 JSON（时间、名次、榜首、差距），不把旧分数对应的名次贴到新分数上。
- 平台代码上传有硬体积上限（如 1 GB），超限**静默被拒**；打包前查体积。
- 浏览器自动化投递：终点击可能触发权限拦截，A / B 榜授权不互相外推；
  多赛题时出候选直接派提交子代理，总控不自己点（见 comp-campaign）。

## 多账号调度（规则允许时）

每个账号记录历史最优、今日剩余、上一发内容；探针分散到非最优账号，
最优账号保持「榜上最优 + 保底回滚」。禁止多账号的比赛严格单账号。

## 线上反馈的保守利用

测试集无真值、样本点个位数时，只做全局、低自由度的拟合（统一位移 / 缩放 / 分组常数），
逐日 / 逐样本自由参数 = 对噪声过拟合。每条从线上归纳的规律标注适用边界，换赛段重新探测。
