# comp-experiment：竞赛实验纪律

竞赛迭代期唯一的复利资产是**可信的实验记录**。这套纪律来自两轮完整实战：
一场时间序列决策赛（数十次实验、赛后逐条可复现），以及一次七题并行的 CV / 语音赛
（数百次实验、上百次线上提交，绝大多数「离线涨」没有兑现成「线上涨」）。
第二轮实战把重点从「怎么做实验」推进到**「怎么判断一个实验结果是不是真的」**。

## 铁律

1. **单变量改动**。一次实验只改一个东西，其余配置、seed、折切分、推理设置全部冻结。
   「为了能跑」而顺手降 batch、换设备、改 eval 频率，都会同时改变 BN 统计 / 有效 LR /
   采样点，结果不再可比。宁可等资源窗口。
2. **固定 seed 与折切分，按来源组切**。时间序列按天整块切；图像 / 视频 / 音频按
   **来源组**（同一原始视频、同一底图及其增强副本、同一说话人、同一拍摄批次）切。
   随机按行切必泄漏。所有实验共用同一套折。
3. **泄漏检查前置**。写特征前对照「测试期可用列清单」（comp-init 数据审计产物）。
   用于「选哪些样本做处理」的分组特征，**必须用生产代码同一份实现、同一套参数重算**，
   同名列不等于同口径（实战：阈值参数不同导致触发集合只有一半重叠，离线增益出包后减半）。
4. **同口径对照**。判定指标必须与基线**同权重口径、同设备、同 dev 集、同后处理**。
   跨设备（MPS / CUDA / CPU）、跨推理设置、中间轮次 argmax 与终局 TTA 之间的数字
   只能看趋势，**不能相减**。实战里两个口径差 0.11，比观察到的「增益」还大。
5. **证据分级**。smoke（几步冒烟）/ 独立 dev / 公开榜（A）/ 终榜（B）严格分开记录，
   诊断性小跑不得写成正式训练；「计划产出」不得写成「已产出」，写之前 `ls` 产物。
6. **失败也要记**。被证伪的方向汇入复盘的证伪清单；同时写清**它依赖的前提**——
   一个结论关掉的方向越多，越要回头检查前提本身有没有被测过。
7. **产物留痕**。每份提交产物记 SHA-256 + 精确字节数（冻结登记用的就是这两项）+ MD5。
   产物不入 git，指纹 + 生成脚本 + 配置在日志里。
8. **训练在跑时绝不编辑它 import 的源文件**。DataLoader worker 会重新导入模块，
   已构造对象仍用旧类定义，崩在 `__getitem__`。要改先 `cp` 快照。崩溃后清掉半截
   run 干净重启，不要 resume——被污染的对照关系修不回来。

## 验证协议先于建模

拿到数据后第一件事不是训 baseline，是**定验证协议**，否则之后所有离线数字都不可信。

1. **审计分组结构**：文件名后缀（`_aug1`）、EXIF / `creation_time`、缩略图近重复、
   case_id 前缀，找出真实独立样本数。实战：1205 个视频片段实为 40 个来源组；
   702 张图实为 351 个底图。
2. **量化分组泄漏**：构造一个「只看得到泄漏信号、看不到任务信号」的代理探针
   （如中间帧 32×32 灰度缩略图 + 1-NN，它根本看不到动作），分别在随机分层与按组划分
   下跑一遍，差值就是随机划分的高估幅度（实战 +0.33）。几分钟跑完，比争论方法论有说服力。
3. **分组与分层冲突时先裁决**：来源组全部单一类别、稀有类只有 1 组，GroupKFold 与
   StratifiedKFold 直接冲突——建模前写明选哪个、代价是什么（某类离线不可估）。
4. **配对 bootstrap CI 按来源组重采样**，每次重算完整官方指标，不把逐图 AP / 逐折 F1
   平均后当官方量；组数 < 10 时 CI 只作描述，必须同时报逐组 Δ。
5. **dev 集被反复用于选模后就不再新鲜**：同一留出集看过第二次的实验改称「探索」，
   选参只用开发切，冻结后再看留出。

## 单步分辨率与暴露度：离线差异能不能被线上测出来

详见 `references/resolution-and-exposure.md`。核心两条：

- **单步分辨率**：翻动 1 个预测单元，线上指标变多少（分类 1/N；F1 反解每条线 /
  每个实例；稀有类单独算）。**小于它的线上差异是噪声，不是证据**——
  实战因此撤回了三条误判的「线上证伪」。
- **暴露度**：候选相对线上锚点改动了多少个预测单元。它是**必要条件（能否被测出）、
  不是充分条件（不决定正负）**。离线显著为正 + 暴露度过门才投；离线增益集中的类别
  在测试集里样本极少时，再大的离线增益也测不出来（+.068 只换来 17 个翻转）。

## 预登记门禁：事前写死，事后不调

详见 `references/gate-design.md`。每个实验开跑前，把判据写进 experiment-log
（或用 `/comp-gate` 命令）：

- 阈值、口径、数据集、对照臂**事前写死**，事后不许调阈值，也不许**事前宣布结论**
  （中途轨迹的逐轮差不具预测力，判定等终局）。
- 判据**无缝覆盖**所有可能结果，每段写明处置**以及不做什么**（不变体化、不改门再试）。
- 已知「A 类有效、B 类有害」的方向，改进版必须加**否决门**：B 类不得恶化超过
  1 个等效实例；只满足主门的判为换包装，方向关闭。
- 门禁写成脚本（`comp-submit/assets/gate_candidate.py` 脚手架），exit code 0 才放行，
  并**用已知线上崩盘的候选做回归验证**——能拦下它才算数。
- 门禁的准入指标要**对准瓶颈维度**，不是总分（「总分涨、瓶颈维恶化」是可识别的失败签名）。

## 诊断先于优化

详见 `references/diagnosis-playbook.md`。两个触发点：

- **动手前**：审计管线里已有的再平衡机制（采样器 / 类别权重 / 决策权重重搜）——
  同轴的新干预会被它们吸收；检查预处理（resize / crop / normalize）删掉了哪些量；
  检查数据的原子结构（时长只有三个离散值时，「更细分桶」没有对应物）；
  架构改动先在 CPU 上跑 3 步（初始等价、新增信息非常量、超参 diff 为空、exit 0）；
  后备方案也先零成本定价，不凭机理直觉排队。
- **连续多个机理不同的方向撞同一堵墙时停下来诊断**，不要换第五个方向。
  把 FN 分成「看到了但没敢判」（p 显著高于负类基线，可攻）与「根本没看见」
  （p ≈ 负类基线，信息不在输入里，放弃），用「可达的 oracle」而非名义 oracle 排优先级。

## 「本地满分」是危险信号

- 公开集与隐藏集是不是**同一个生成批次**？穷举公开集句式 / 模板拿到 100 分，
  隐藏集换模板就全部落空（实战：本地 100.0，线上 6.14，恰等于全兜底常数策略）。
- **兜底路径的得分就是下限**，必须单独测；多种常数策略里挑最高的那个当兜底。
- **首发要尽早交**，用来测线上-线下差值，不要等「做到满分再交」。

## 离线↔线上标定库

每次线上提交后，把（离线 Δ, 线上 Δ, 暴露度, 是否有不跨零 CI, dev 域是否匹配）
追加到日志。定期回看：

- **离线能否外推，取决于「验证集域是否匹配」+「是否带不跨零的 CI」，不取决于离线数值多大。**
  这条**只能单向用**：有它则可放心投；没有它不等于该弃（实战有无 CI 却线上 +0.8 的反例）。
- 离线负向结论在线上通常方向一致且幅度被低估——门禁体系保守可靠；
  离线正向兑现率才是需要标定的量。
- 不相关 / 反向时立刻停止刷离线指标：切换到与测试期同分布的训练窗口 / 代理集做对照，
  在真实测试集上跑**无标签代理指标**（预测数、空图数、长度 / 面积比、前景占比、均值概率），
  它们能暴露模型在未见域上变保守 / 变激进。
- 结果对自己有利时更要质疑归因：重搜权重口径下的漂亮数字若恰好是已知的假增益来源
  （校准自由度），警觉要更高而不是更低。**方向正确 ≠ 口径正确。**

## verify 脚本文化

每个假设一个独立验证脚本 `src/verify_<假设>.py`：自包含、能独立重跑、
输出指标对比 + `caveat` 字段（如「oracle ≠ 融合可得」）随 JSON 一起落盘。
先离线证实再上线；离线证伪的直接记日志。验证维度不止 OOF 均值：跨组 / 跨折 / 跨季
稳定性、seed 敏感度、按折均衡（增益只来自单折 = 假信号）。

## 实验记录格式

日志在 `docs/experiment-log.md`，新记录加在顶部，标题
`## <日期> <方法一句话>（<结果标签：新高 X / 微增 / 证伪 / 管道验证 / 外部约束关闭>）`。
字段见 `references/experiment-log-template.md`。**「没跑成」（OOM / 权重拉不到 / 平台失败）
与「没效果」是两个标签**，混写会把可行的轴永久埋掉。

写完一次实验的完整闭环：

1. 预登记判据（`/comp-gate`）。
2. 改动实现在 `src/`，跑 verify / OOF，得同口径指标 + 暴露度。
3. 过门才生成提交产物，算 SHA-256 / 字节数 / MD5，放 `submissions/<方案名>/`。
4. 提交后回填回执（时间、额度前后值、回读指纹、线上得分）。
5. 写**结论**：回答了什么问题、下一步做什么或放弃什么、这条结论依赖什么前提。
