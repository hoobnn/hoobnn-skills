# comp-experiment：竞赛实验纪律

竞赛迭代期唯一的复利资产是可信的实验记录。这套纪律来自两轮实战（时间序列决策赛数十次实验；
七题并行 CV / 语音赛数百次实验、上百次提交），第二轮最大的教训是：**绝大多数「离线涨」没有兑现成
「线上涨」**。所以重点不只是怎么做实验，而是怎么判断一个结果是不是真的。

## 可比性：一个实验只改一个东西

- 一次只改一个变量，其余配置、seed、折切分、推理设置全部冻结。「为了能跑」顺手降 batch、换设备、
  改 eval 频率，会同时改变 BN 统计、有效 LR 与采样点，结果就不再可比——宁可等资源窗口。
- 判定指标与基线同权重口径、同设备、同 dev 集、同后处理。跨设备（MPS / CUDA / CPU）、中间轮次 argmax
  与终局 TTA 之间的数字只能看趋势，不能相减；实战里两个口径差 0.11，比「增益」本身还大。
- 「选哪些样本做处理」的分组特征，用生产代码同一份实现、同一套参数重算。同名列不等于同口径
  （阈值参数不同导致触发集合只有一半重叠，离线增益出包后减半）。
- 训练在跑时不编辑它 import 的源文件：DataLoader worker 会重新导入模块，已构造对象仍用旧类定义，
  崩在 `__getitem__`。要改先 `cp` 快照。崩溃后清掉半截 run 从零重启，不 resume，被污染的对照关系修不回来。

## 验证协议先于建模

拿到数据后第一件事不是训 baseline，是定验证协议，否则之后所有离线数字都不可信。

1. **审计分组结构**：文件名后缀（`_aug1`）、EXIF / `creation_time`、缩略图近重复、case_id 前缀，找出真实
   独立样本数（实战：1205 个视频片段实为 40 个来源组；702 张图实为 351 个底图）。时间序列按天整块切，
   图像 / 视频 / 音频按来源组切，所有实验共用同一套折。
2. **量化泄漏**：构造一个只看得到泄漏信号、看不到任务信号的弱特征（如中间帧 32×32 灰度缩略图），
   用 `assets/leak_probe.py` 跑 1-NN，分别在随机分层与按组划分下评估，差值就是随机划分的高估幅度
   （实战 +0.33）。几分钟跑完，比争论方法论有说服力。
3. **分组与分层冲突时先裁决**：来源组全部单一类别、稀有类只有 1 组时 GroupKFold 与 StratifiedKFold 直接冲突，
   建模前写明选哪个、代价是什么（某类离线不可估）。
4. **CI 按来源组做配对 bootstrap**（`assets/paired_bootstrap.py`），每次重算完整官方指标，不把逐图 AP /
   逐折 F1 平均后当官方量；组数 < 10 时 CI 只作描述，同时报逐组 Δ。
5. 泄漏检查对照 comp-init 数据审计产出的「测试期可用列清单」。dev 集用于选模第二次后就不再新鲜：
   选参只用开发切，冻结后再看留出。

## 这个差异是不是真的

三个工具，各有一份参考文件；计算部分已脚本化在 `assets/`（拷到仓库 `src/` 用）：
`step_resolution.py` 标定单步分辨率，`exposure.py` 算暴露度与流向定价，`paired_bootstrap.py` 出组级 CI，
`leak_probe.py` 量化分组泄漏。

- **单步分辨率与暴露度**（`references/resolution-and-exposure.md`）：翻动 1 个预测单元线上指标变多少，
  小于它的线上差异是噪声不是证据（实战因此撤回三条误判的「线上证伪」）；候选相对线上锚点改动了多少
  个单元决定它能不能被测出，但不决定正负。
- **预登记门禁**（`references/gate-design.md`，命令 `/comp-gate`）：阈值、口径、对照臂、处置表在开跑前写死，
  判据无缝覆盖所有结果区间且每段写明不做什么；已知「A 类有效 B 类有害」的方向要有否决门；门禁写成脚本，
  用已知线上崩盘的候选做回归验证。
- **零成本诊断**（`references/diagnosis-playbook.md`）：动手前审计已有的再平衡机制（同轴干预会被吸收）、
  预处理删掉了哪些量、信息有没有路径到达决策层；连续多个机理不同的方向撞同一堵墙时停下来诊断，
  把 FN 分成「看到了没敢判」（可攻）与「根本没看见」（信息不在输入里，放弃）。

## 离线↔线上标定

每次提交的回执带 `offline` 块（离线 Δ、CI 下界、暴露度、dev 域是否匹配），出分后回填，
`receipts.py calibrate` 直接渲染标定表与兑现率（脚本在 comp-submit `assets/`）。定期回看：

- 离线能否外推取决于「dev 域匹配 + CI 不跨零」，不取决于离线数值多大。这条只能单向用：有它可放心投，
  没有它不等于该弃（实战有无 CI 却线上 +0.8 的反例）。
- 离线负向结论在线上通常方向一致、幅度被低估；需要标定的是正向兑现率。
- 离线线上不相关时停止刷离线指标，切到与测试期同分布的代理集，并在真实测试集上跑无标签代理指标
  （预测数、空图数、长度 / 面积比、均值概率），它们能暴露模型在未见域上变保守或变激进。
- 结果对自己有利时更要质疑归因：重搜权重口径下的漂亮数字若恰是已知的假增益来源（校准自由度），
  警觉要更高而不是更低。方向正确 ≠ 口径正确。
- 「本地满分」是危险信号：公开集与隐藏集是否同一生成批次？穷举公开集模板拿 100 分，隐藏集换模板就
  落到全兜底常数策略的分数（实战本地 100.0，线上 6.14）。兜底路径单独测，首发尽早交。

## 记录

日志在 `docs/experiment-log.md`，新记录加顶部，字段与样例见 `references/experiment-log-template.md`
（命令 `/comp-log`）。几处容易写歪：

- 证据分级严格分开：smoke / 独立 dev / A 榜 / B 榜。诊断性小跑不写成正式训练；「计划产出」不写成
  「已产出」，写之前 `ls`。
- 结果标签三分：**证伪**（幅度远超单步分辨率，或两个独立数据点互证）/ **不可分辨**（小于单步）/
  **外部约束关闭**（OOM、权重拉不到、平台失败）。后两类不是死路，混写会把可行的轴永久埋掉。
- 失败也要记，并写清它依赖的前提：一个结论关掉的方向越多，越要回头检查前提本身有没有被测过。
- 每个假设一个自包含的 `src/verify_<假设>.py`，输出指标对比与 `caveat`（如「oracle ≠ 融合可得」）落盘 JSON。
  验证维度不止均值：跨折 / 跨组稳定性、seed 敏感度；增益只来自单折是假信号。
- 产物不入 git，记 SHA-256 + 精确字节数（冻结登记用这两项）+ MD5，连同生成脚本与配置。

一次实验的完整闭环：预登记判据 → 改动 + verify / OOF，得同口径指标与暴露度 → 过门才出包并算指纹 →
提交后回填回执 → 写结论（回答了什么问题、下一步做什么或放弃什么、依赖什么前提）。
