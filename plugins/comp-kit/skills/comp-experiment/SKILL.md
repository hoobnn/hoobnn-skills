# comp-experiment：竞赛实验纪律

竞赛迭代期唯一的复利资产是**可信的实验记录**。这套纪律来自完整实战：
数十次实验、多模型对照、赛后仍能逐条复现每个结论，靠的就是下面的规矩。

## 铁律

1. **单变量改动**。一次实验只改一个东西（特征 / 模型结构 / 训练窗口 / 损失），
   其余配置、seed、折切分全部冻结。改了两个变量的实验得不出任何结论。
2. **固定 seed 与折切分**。OOF 用固定 seed、按天（或按组）切折——时间序列必须按天整块切，
   随机按行切会泄漏。所有实验共用同一套折，指标才可比。
3. **泄漏检查前置**。写特征前先对照"测试期可用列清单"（comp-init 数据审计的产物）：
   任何依赖测试期拿不到的信息（历史真实标签的 lag/rolling、未来信息）的特征，
   训练时能算 ≠ 推理时能用。实战教训：本地 14028 vs 线上 4106，主因正是分布外 + 训练测试信息不对称。
4. **失败也要记**。被证伪的方向和被证实的一样值钱——它们最终汇入复盘的"证伪清单"，
   防止一个月后自己（或队友、或换个 agent）重走死路。
5. **产物留痕**。每份提交文件记录 MD5。产物不入 git，但 MD5 + 生成脚本 + 配置在日志里，
   任何一份历史提交都能指认来源。

## verify 脚本文化

每个假设一个独立验证脚本，命名 `src/verify_<假设>.py`，例如
`verify_feat_oof.py`、`verify_decision_rules.py`、`verify_extrap_crossseason.py`。

- 脚本自包含：加载数据 → 构造对照 → 输出指标对比，能独立重跑。
- 先离线证实，再考虑消耗线上提交次数；离线证伪的直接记日志、不上线。
- 验证维度不止 OOF 均值：跨季稳定性（分季节看）、跨折方差、对 seed 的敏感度。
  OOF 只涨在某一折或某一季的"提升"多半是噪声。

## 指标体系：对着上下界看

不看裸指标，看**捕获率**：

- `捕获率 = 当前方案离线收益 / oracle 上界收益`（comp-init 已锚定上下界）。
- 中间指标（RMSE / MAE / AUC）只用于诊断，**不作为方案取舍依据**——
  评分公式只看什么，取舍就只看什么。实战里 RMSE 更好的模型线上反而更差是常态。
- 排序类决策任务补充排序指标（如 Kendall τ）：决策只依赖相对大小时，排序比绝对值更接近真金白银。

## 线上线下相关性监控

每次线上提交后，把（离线指标, 线上得分）追加到日志。定期回看：

- **相关 → 继续信任离线迭代**，加大离线实验密度、节省提交次数。
- **不相关/反向 → 立刻停止刷离线指标**，这是分布漂移的信号。此时该做的是：
  切换到与测试期更同分布的训练窗口做对照（如只用最近一个季度）、检查测试期特有 regime、
  把线上反馈本身当作稀缺数据点直接拟合（见 comp-submit 的探针策略）。
- 实战规律：全年 OOF 最优 ≠ 线上最优；时间邻近的训练窗口在漂移场景下常反超。

## 实验记录格式

日志在 `docs/experiment-log.md`，**新记录加在文件顶部**（倒序），标题格式
`## <日期> <方法一句话>（<结果标签，如：新高 6868 / 证伪>）`。
每条必含字段见 `references/experiment-log-template.md`。

写完一次实验的完整闭环是：

1. 改动实现在 `src/`（新脚本或明确 diff）。
2. 跑 verify / OOF，得指标。
3. 生成提交产物（若上线），算 MD5，产物放 `submissions/<方案名>/`。
4. 提交后回填 submitId、状态、线上得分、该账号剩余次数。
5. 写**结论**：这次实验回答了什么问题，下一步做什么或放弃什么。没有结论的记录是无效记录。
