# 预登记门禁设计

门禁 = 实验开跑前写死的判据。它防两件事：事后调阈值，和事前提前宣布结论。七题实战里主动弃投的
候选多于实际投出的，这是纪律在起作用。

## 预登记内容

| 项 | 要求 |
|---|---|
| 对照臂 | 唯一线上验证过的锚点，不是「上一个离线最好」；与候选同口径 |
| 唯一变量 | 一句话，其余全部冻结（含推理设置、设备、后处理） |
| 主门阈值 | 用单步分辨率换算（≥ 3 步），不拍整数 |
| 否决门 | 代价侧不得恶化超过 1 个等效实例 |
| 暴露度门 | 相对线上锚点 ≥ 门槛 |
| 口径 | 权重（冻结 / 重搜）、设备、dev 集、TTA、后处理 |
| 处置表 | 穷举所有结果区间，每段写处置 + 不做什么 |
| 资源门 | 显存 / 内存峰值预算、smoke 步数、超时；不满足则不判定、不降 batch |

用 `/comp-gate` 写进 experiment-log，或写进 receipt JSON（比文档更难事后改）。

## 处置表无缝覆盖，每段写「不做什么」

有缝的判据等于没有判据：`<88.7 回退 / [缝] / 89.1~89.3 关闭 / [缝] / ≥89.5 成立`。缝隙恰恰是最可能落的
区间，也最容易被说成「接近 89.5，算成立吧」。

| 结果 | 处置 |
|---|---|
| 主门过 + 否决门过 + 归因相符 | 提交（唯一该投的情形） |
| 主门过、否决门不过 | 不投，判「换包装」，不变体化 |
| 主门不过、目标类正向 | 不投，记「机理成立幅度不足」，保留结论不保留候选 |
| 两者都不过 | 不投，方向关闭：不改注入位置、不加强度旋钮、不回试已否定档位 |
| 未跑满 / OOM | 不判定；不降 batch（同时改 BN 统计与有效 LR） |

最差区间预设诊断分支（如查计数是否全落 fallback 桶），区分算法问题与环境问题。「再试一个边界看看」
是最典型的额度消耗方式，每次都显得成本很低，只有事前写死「不变体化」才挡得住。不因「比失败臂好」
放宽门禁：拿失败臂当参照系是移动球门。

## 否决门：区分「解决了冲突」与「换了个包装」

已知某方案「A 类有效、B 类有害」时，改进版必须同时证明 A 类仍有效且 B 类不再受害。实战：三视图加回
近视野后 small 增益几乎不变（+0.0236 vs +0.0239），cracked 仍负（−0.0196），只是把宽视野换了个包装。
没有否决门，仅看主门为正 + 归因相符，很容易读成「机理成立、只是幅度不够」然后继续投变体。

否决门阈值按该类的单例敏感度设；对「信息不在输入里」的类只设不恶化下限，不设改善要求。

## 脚本化 + 回归验证

- 写成 `src/gate_candidate.py`（脚手架在 comp-submit `assets/`），阈值与锚点常数写死在脚本，exit 0 才放行，
  verdict JSON 每条门带 `why`。
- 用已知线上崩盘的候选做回归验证：旧判据放行、新门禁拦下，才证明门禁抓住了旧直觉抓不到的东西。
  基线跟自己比 gain=1.5e-08 正确判 fail，证明常数与实际逐位吻合。
- 准入指标对准瓶颈维度，不是总分。实战两个候选都是「总 dev mAP 涨、分类损失恶化」，其中一个线上
  −0.029；门禁改为「`classification_loss` 不得高于锚点」后拦下了另一个。

## 几条常被绕过的边界

- **判定等终局**：中途轨迹的逐轮差不具预测力，尤其中间量与最终口径不同（argmax vs TTA + 冻结权重差
  +0.026）。实战在 ep3 外推「不可达」，ep4 就反超，基线 ep4 恰是它自己的低谷。
- **数值变更后旧结论作废**：换量化格式、后端、后处理后，此前基于旧数值的结论一律重跑，无论方向看起来
  是好是坏。实战重跑后发现旧结论低估了候选。「预期只会更好」不是证据。
- **修改上游产物**（官方模型 / 图）要做同协议对照并给出数据，如实表述为「解决运行时可用性，不是拿它
  换质量」。
- **纪律要有执行路径**：「下载前先预估相关性」与「算相关性得先下权重」互相矛盾时，拆两级，第一级用
  零成本的必要条件（血统预筛：训练集 / 团队 / 骨干任一与现役成员同源即淘汰），过了才下权重实测。
  写下任何「先评估再投入」类规则后，检查评估本身是否需要投入；每段处置引用的脚本、包、清单要真实存在。
- **资源阈值同样要执行路径**：谁来检测、触发后停什么（指定牺牲顺序）、善后是什么（删干净、日志改名
  `.aborted.log`、禁止 resume）。三者缺一，阈值只是个数字。
