# comp-retrospective：阶段复盘与答辩材料

复盘不是流水账，是**下一阶段的作战手册**。原料是 `docs/experiment-log.md` 的逐条记录、
提交回执与榜单快照，产出是「什么有效 / 什么是死路 / 新数据来了先做什么」。

## 何时写

- 赛段切换：初赛→复赛、复赛→决赛，拿到新数据**之前**写完。
- 赛后：完整复盘归档，供下一场比赛与个人方法论沉淀。
- 赛中长滞涨（一周无新高）或连续多个方向撞同一堵墙时写小复盘，防止惯性消耗。
- 多赛题并行时每隔几天把跨题规律沉淀进工作区 `METHODOLOGY.md`（见「跨赛题方法论」）。

## 复盘文档结构

文件放 `docs/<阶段>复盘.md`，模板见 `references/retrospective-template.md`。各节要点：

1. **一句话结论**：靠什么方法、从多少分打到多少分、排名、最重要的一条教训。
2. **题目机制硬约束**：从 requirements 抄最容易踩的几条，新阶段规则可能变，逐条核对。
3. **最有效方法**：主框架、执行器脚本、**为什么有效**（成立前提决定它在新数据上是否还成立）。
4. **已验证规律 ⚠️ 标注适用边界**：仅在哪个测试集 / regime 成立、成因假设、新阶段是否需重验。
   「有不跨零 CI 且 dev 域匹配 ⇒ 可外推」只能单向使用。
5. **证伪清单**：逐条写方法 + 死因 + 证据分数 + **依赖的前提**。三类必须分开：
   - **证伪**：幅度远超单步分辨率，或两个独立数据点互证。
   - **不可分辨**：线上差异小于单步分辨率——不是证伪，候选可作后续基座。
     复盘时回头检查已有的「证伪」里有多少其实属于这一类（实战撤回三条）。
   - **外部约束关闭**：OOM / 权重拉不到 / 平台失败——轴没被测过，别当死路。
6. **离线↔线上标定库**：每次提交的（离线 Δ, 线上 Δ, 暴露度, 有无 CI, 域是否匹配）汇表，
   得出本题的兑现率与方向一致性；这是下一阶段判读离线数字的依据。
7. **可复用资产清单**：直接搬 / 需改造 / 归档（校验器、门禁脚本、评测复现、出包链、守夜脚本）。
8. **下一阶段作战计划**：拿到新数据后的前三件事（管道精确复现 → 重锚上下界与单步分辨率 →
   重验规律方向与幅度），以及冻结 / 登记死线。

## 跨赛题方法论（多赛题工作区）

七题并行实战里，最有价值的产出是跨题规律（单步分辨率、暴露度、再平衡吸收、
「信息在不在图里」……），它们沉淀在工作区级 `METHODOLOGY.md`，每条附来源赛题与数据。

- **跨赛题规律是「待验证的假设」而非「已知的事实」**：转发到另一题时说「可能同构」，
  接收方逐条读源码验证，把「可能」变成确定的「是」或「否」，两种结论都算交付。
- 每条规律写明**适用前提**（如「统计量会被减掉 / 除掉」才成立，分层评估不受此限）。
- 成熟的规律回流到本 skill 集：写进 comp-experiment 的 references。

## 归档纪律

- 冲刺期临时脚本与产物移入 `archive/<阶段>冲刺/`，`src/` 只留下一阶段还要用的资产。
- experiment-log 与回执不动——它们是原始台账；复盘是提炼视图，两者互链。
- 归档前核对「目录里多了什么」（多代理并行时产物目录不是私有的），
  带 `DO NOT SUBMIT` 标记的中间产物不进资产清单。

## 答辩材料（晋级决赛时）

放 `docs/决赛答辩/`，按编号从底层材料到最终讲稿逐层加工：

```
docs/决赛答辩/
├── 00-答辩总览与PPT路线.md   # 叙事主线
├── 01-全程历程与分数轨迹.md   # 分数曲线 + 关键转折点
├── 02-最终技术方案.md
├── 03-实验与证伪全记录.md     # 从 experiment-log 提炼，体现工作量与严谨性
├── 04-答辩QA弹药.md           # 预判问题 + 弱点的诚实回答
├── 05-领域与原理基础QA.md
├── 06-决赛答辩PPT内容.md
├── 07-答辩稿.md
└── assets/
```

要点：分数轨迹是最有说服力的叙事，每个跳变对应一个方法决策；
证伪记录是加分项不是家丑；改动上游产物（官方模型 / 图）要有同协议对照数据
（「解决运行时可用性，不是拿它换质量」）；QA 里最重要的是弱点问题的诚实回答
（「线下线上为什么不一致」→ 用标定库回答）。PPT 文案先在 markdown 定稿再排版。
