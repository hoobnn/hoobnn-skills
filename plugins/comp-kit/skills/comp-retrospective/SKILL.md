# comp-retrospective：阶段复盘与答辩材料

复盘不是流水账，是**下一阶段的作战手册**。原料是 `docs/experiment-log.md` 的逐条记录，
产出是"什么有效 / 什么是死路 / 新数据来了先做什么"。

## 何时写

- 赛段切换：初赛→复赛、复赛→决赛，拿到新数据**之前**写完。
- 赛后：完整复盘归档，供下一场比赛与个人方法论沉淀。
- 赛中长滞涨（一周无新高）也值得写个小复盘，防止在死路上惯性消耗。

## 复盘文档结构

文件放 `docs/<阶段>复盘.md`（如 `初赛复盘.md`），结构见
`references/retrospective-template.md`。各节要点：

1. **一句话结论**：靠什么方法、从多少分打到多少分、排名、最重要的一条教训。
   写不出一句话说明还没想清楚。
2. **题目机制硬约束**：从 requirements 里抄最容易踩的几条，新阶段规则可能变，逐条核对。
3. **最有效方法**：主框架是什么、为什么有效、执行器是哪个脚本。
   "为什么有效"必须写——它决定该方法在新数据上是否还成立。
4. **已验证规律 ⚠️ 标注适用边界**：每条规律注明"仅在 <哪个测试集/regime> 成立、
   成因假设是什么、新阶段是否需要重验"。实战教训：初赛测试集的三条规律全部源于
   该时段特有 regime，复盘里若不标注，复赛会当成真理直接套用。
5. **证伪清单**：死路逐条列出（方法 + 死因 + 证据分数）。这是复盘里防止重复烧预算
   最值钱的一节。
6. **可复用资产清单**：哪些脚本 / 函数 / 校验器直接搬到下一阶段
   （如公共数据加载、DP 求解器、window 执行器、提交校验器），哪些要重写。
7. **下一阶段作战计划**：拿到新数据后的前三件事（通常是：重验旧规律方向与幅度、
   重锚上下界、管道精确复现验证）。

## 归档纪律

- 冲刺期的临时脚本与产物移入 `archive/<阶段>冲刺/`，`src/` 只留下一阶段还要用的资产。
- experiment-log 不动——它是原始台账；复盘是它的提炼视图，两者互链。

## 答辩材料（晋级决赛时）

放 `docs/决赛答辩/`，按编号组织，从底层材料到最终讲稿逐层加工：

```
docs/决赛答辩/
├── 00-答辩总览与PPT路线.md   # 叙事主线：评委要听什么、按什么顺序讲
├── 01-全程历程与分数轨迹.md   # 分数曲线 + 关键转折点，讲"故事"的原料
├── 02-最终技术方案.md         # 技术栈全景，答辩版（非论文版）
├── 03-实验与证伪全记录.md     # 从 experiment-log 提炼，体现工作量与严谨性
├── 04-答辩QA弹药.md           # 预判问题 + 准备好的回答（含弱点的诚实应对）
├── 05-领域与原理基础QA.md     # 领域知识兜底（评委可能考基础）
├── 06-决赛答辩PPT内容.md      # 逐页文案
├── 07-答辩稿.md               # 带舞台提示的讲稿
└── assets/                    # 图表
```

要点：

- **分数轨迹是最有说服力的叙事**：每个跳变对应一个方法决策，讲"我们如何发现→验证→放弃/采用"。
- **证伪记录是加分项不是家丑**：完整的否定结果展示的是实验纪律，评委看重。
- QA 弹药里最重要的是**弱点问题的诚实回答**（如"你们线下线上为什么不一致"），
  提前写好比现场硬掰强得多。
- PPT 生成可配合 pptx 类 skill；文案先在 markdown 里定稿再排版。
