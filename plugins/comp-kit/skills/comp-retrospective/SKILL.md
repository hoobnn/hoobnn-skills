# comp-retrospective：阶段复盘与答辩材料

复盘是下一阶段的作战手册，不是流水账。原料是 experiment-log、回执与榜单快照，产出是「什么有效 /
什么是死路 / 新数据来了先做什么」。

## 何时写

- 赛段切换：拿到新数据**之前**写完。
- 赛后：完整归档，供下一场与个人方法论沉淀。
- 赛中一周无新高、或连续多个方向撞同一堵墙时写小复盘，防止惯性消耗。
- 多赛题并行时每隔几天把跨题规律沉淀进工作区 `METHODOLOGY.md`。

## 复盘文档

文件 `docs/<阶段>复盘.md`，模板见 `references/retrospective-template.md`（命令 `/comp-retro`）。各节容易写浅的地方：

1. **一句话结论**：靠什么方法、从多少分打到多少分、排名、最重要的一条教训。
2. **题目机制硬约束**：从 requirements 抄最容易踩的几条；新阶段规则可能变，逐条标「待核对」。
3. **最有效方法**：写清**为什么有效**，成立前提决定它在新数据上是否还成立。
4. **已验证规律**：标注仅在哪个测试集 / regime 成立、成因假设、新阶段是否需重验。
   「有不跨零 CI 且 dev 域匹配 ⇒ 可外推」只能单向使用。
5. **证伪清单**：方法 + 死因 + 证据 + 依赖的前提。三类分开：**证伪**（幅度远超单步分辨率或两个独立
   数据点互证）/ **不可分辨**（小于单步，候选可作后续基座）/ **外部约束关闭**（轴没被测过）。
   回头检查已有的「证伪」里有多少其实属于后两类，实战撤回三条。
6. **离线↔线上标定库**：`receipts.py calibrate --step <单步>` 直接渲染（离线 Δ、暴露度、CI、域匹配、
   线上 Δ 与步数）汇表和兑现率；复盘要做的是读表下结论：本题离线正向兑现率多少、负向是否同向、
   什么条件下可信离线，这是下一阶段判读离线数字的依据。
7. **可复用资产**：校验器、门禁脚本、评测复现、出包链、守夜脚本，各标直接搬 / 需改造 / 归档。
8. **下一阶段计划**：拿到新数据后的前三件事（管道精确复现 → 重锚上下界与单步分辨率 → 重验规律的
   方向与幅度），以及冻结 / 登记死线。

## 跨赛题方法论

跨题规律（单步分辨率、暴露度、再平衡吸收、「信息在不在图里」）是七题实战最有价值的产出，沉淀在工作区
`METHODOLOGY.md`，每条附来源赛题、数据与适用前提。转发到另一题时它是**待验证的假设**：说「可能同构」，
接收方逐条读源码验证，「是」与「否」都算交付。成熟的规律回流到 comp-experiment 的 references。

## 归档

- 冲刺期临时脚本与产物移入 `archive/<阶段>冲刺/`，`src/` 只留下一阶段还要用的资产。
- experiment-log 与回执是原始台账，不动；复盘是提炼视图，两者互链。
- 多代理并行时产物目录不是私有的，归档前核对「目录里多了什么」；带 `DO NOT SUBMIT` 标记的中间产物
  不进资产清单。

## 答辩材料（晋级决赛时）

放 `docs/决赛答辩/`，按编号从底层材料到最终讲稿逐层加工：`00-总览与PPT路线`、`01-历程与分数轨迹`、
`02-最终技术方案`、`03-实验与证伪全记录`、`04-答辩QA弹药`、`05-领域与原理基础QA`、`06-PPT内容`、
`07-答辩稿`，附 `assets/`。

分数轨迹是最有说服力的叙事，每个跳变对应一个方法决策；证伪记录是加分项不是家丑；改动上游产物要有
同协议对照数据；QA 里最重要的是弱点问题的诚实回答（「线下线上为什么不一致」用标定库回答）。
PPT 文案先在 markdown 定稿再排版。
