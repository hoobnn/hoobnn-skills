# comp-campaign：多赛题并行总控

一人（或一个总控代理）同时推进多题时，稀缺资源变成三种：**提交额度、共享算力、
代理 API 额度**——第三种是唯一会「整队同时归零」的。本 skill 来自七题并行三周的实战。

## 工作区布局

```
<workspace>/
├── CAMPAIGN.md          # 用户授权与完成条件（参赛范围、目标、允许 / 禁止的动作）、接续顺序
├── STATUS.md            # 看板：截止 / 冻结日历、各题线上最佳与名次、今日额度、在跑与下一步
├── METHODOLOGY.md       # 跨赛题方法论（comp-retrospective 沉淀）
├── campaign/
│   ├── <日期>-receipts.md      # 当日全部投递回执（comp-submit receipt 字段）
│   ├── <日期>-leaderboard.json # 榜单快照（时间、名次、榜首、差距）
│   ├── <日期>-prepared.json    # 已备候选（路径 / 指纹 / 门禁结论 / 预登记判读）
│   └── teams-<日期>/           # 子代理编成、章程、交接 HANDOFF
├── scripts/             # 跨题工具（榜单查询、守夜、提交代理入口）
└── <题目仓库>/…         # 各题独立 uv 环境，comp-init 布局
```

看板模板见 `references/status-board-template.md`。三类内容分家：**约束 → 各仓库入口文件；
事实 → 各仓库 experiment-log；状态 → STATUS.md**。新派代理未必读到 STATUS 的某一节，
「今后一律 / 绝不」类规则必须进入口文件。

## 总控职责

1. **提交权归总控**：子代理过门后写 HANDOFF（路径、SHA-256、字节、离线证据、预登记判读），
   由总控或专职提交子代理投递并写回执。浏览器投递的终点击可能被权限分类器拦截，
   派提交子代理而不是总控自己点；A / B 榜授权不互相外推，每次投递前取得用户当次授权。
2. **额度账**：每题每日 / 累计额度、零点刷新；判「投成功」只认额度减 1 + 回读一致。
   「今日额度用尽」必须查平台，不从本地产物日期推断。
3. **日历**：每题 A 榜截止、冻结登记死线（早于 B 榜一天）、B 榜窗口、复赛节点；
   赛程以规则正文为准，免登录接口 curl 核实，不信 API 字段。
4. **目标改写**：按差距 / 单步分辨率 / 剩余天数现实改目标（「冲第一」→「进前 15 + 冻结零事故」），
   差距为量级级别且最先截止的题**放弃**并在入口文件加禁止推进横幅。
5. **裁决前三件事**：远程机器 `nvidia-smi` + 产物目录 `ls`、各仓 `submissions/` mtime 与平台额度、
   接口查截止。上游简报把「计划产出」写成「已产出」是常态，**必须 ls 核实**。
6. **每日节奏**：晨班核实昨夜出分与回执；白班派发；夜班把各题进度固化进 STATUS，
   零点后按额度刷新安排首发；截止前 N 小时的动作单独列。

## 子代理编成与纪律

每题一队（一个子代理，队内角色按顺序扮演），章程写进 `campaign/teams-<日期>/ORG.md`。
全队纪律（违反 = 实验作废）：

1. 提交权在总控；候选过门后只写 HANDOFF。
2. **预登记门禁**：跑实验前把判据写进 team log；事后不改。沿用 METHODOLOGY 全部条款。
3. 单变量；跨设备 / 跨口径不得相减；A 榜单步分辨率之下的差异不是证据。
4. **不重跑已终态实验**：先读仓库 experiment-log 末尾与总控派发单，禁止复活已证伪方向。
5. 证据分级：smoke / 独立 dev / A 榜 / B 榜严格分开。
6. 写回：当天写入仓库 `docs/`，重要结论同步 `outputs/`。
7. 资源纪律见下节；论文检索结论注明「已检索」而非凭记忆；新数据 / 权重登记 SHA 与来源后才可用。
8. **唤醒指令自带地面实况**（进程状态、产物路径、日志尾部读数），省掉代理重新探查的十几轮工具调用。
9. **不给同一任务挂多个守候代理**；多代理并行同一题时产物目录不是私有的，
   收尾核对「目录里多了什么」；发现他人产物有误投风险只改文件名加 `DO NOT SUBMIT`，内容不动。
10. 一条已批准指令的**批准依据**要显式记录；执行前若依据所依赖的测量条件已变（负载降了 3 倍），
    重算并带可复核证据顶回，而不是照做。

## API 限流轮转

9 个代理并行 = 单日两次撞满 5 小时限流，每次冻结全队约 4.5 小时。限流冻结的是代理，
不冻结训练进程，损失的是判定与提交的时机。

- 同时最多 3 个代理活跃，其余待命；按「离截止最近 + 有待判定产物」排序轮转。
- 代理绝不空转等待：长任务由总控 PID 级守夜，进程退出后再唤醒代理。
- 冻结前把各题进度固化进 STATUS.md，恢复后直接接手，严禁重跑已完成实验。

## 共享机器资源仲裁

新 GPU 任务启动前必须打印并落盘（缺一项不许开训）：

```bash
pgrep -af <已知异常进程，如挖矿>; nvidia-smi; free -g; pgrep -af 'python|uv run'
```

- 并发 GPU 任务 ≤ 2~3 路（四路实测把单题 epoch 从 2.4 min 拖到 28 min）；各队只用自己 slot 的显存配额。
- 系统内存常比显存先见底：加臂前看 `free -g` 而不只看 `nvidia-smi`；WSL 下 `nvidia-smi`
  无法逐进程归因显存，多次采样按最小值规划，用 `set_per_process_memory_fraction` 卡自己的上限。
- **CPU 成本按解码像素量估，不按模型容量估**：多视图 / 视频任务默认瓶颈是 CPU 解码，
  `nvidia-smi` 看不出来却拖慢所有人。
- 内存告警要配守卫脚本：指定牺牲顺序（先停哪个臂）、TERM → 20 s → KILL、
  被停的 run 删干净禁止 resume、触发时上报总控。
- 不为「能跑」而破坏单变量：显存不足时写余量门控启动器等窗口，不降 batch。
- 远程机器重启后第一件事查异常进程，再查训练；GPU 全空时各代理会抢着重启，总控重新数并发。
- 训练全部在远程时本机零计算进程；按需 ssh 查询，不挂常驻 tail 管道；用 ControlMaster 复用连接
  （多代理并发各自触发 ssh agent 授权）。

## 守夜与唤醒

模式与脚本见 `references/watchdog-patterns.md`。四条硬规则：

1. **判活看产物增量**（`ls <out>/pred | wc -l`），不看进程存在；KeepAlive 会把每 30 s 崩一次伪装成「在运行」。
2. **三态 ssh 检测**：连接失败 / 进程仍在 / 进程已退出分开处理，远端输出可解析计数，不用退出码承载两个语义。
3. **守夜进程的环境要自检**：launchd / cron 的 PATH 不含 homebrew，`command -v uv || exit 1` 硬失败一次，不空转 20 小时。
4. **长训练可 resume**：`save-every ≤ 2` + `last.pt` + 启动即写 PID / 日志 / 断点路径；
   虚拟机会在宿主不重启的情况下被干净关闭。

## 冻结与 B 榜的总控视角

- 冻结日历单独列：冻结死线比提交死线早；发布前替换登记包合规。
- 演练打包提前 2~3 天，与候选研发抢时间时演练优先。
- B 集发布靠守夜脚本盯；下载后 audit 计数；第一发冻结基座原样。
- 冻结登记入口与打分入口是两个页面；tab 不渲染不等于未开放。
